# Просмотр сайта в Xcode

Отдельное небольшое приложение для проверки текущего сайта в системном браузерном движке iOS — `WKWebView`. Исходники сайта оно не копирует: показывает их с сервера на Mac. Изменил сайт, нажал «Обновить» в приложении — видишь новую версию.

Это инструмент проверки. Он не подключён к Telegram и не предназначен для публикации в App Store. Учётная запись Apple для сборки в симуляторе не нужна.

## Открыть и запустить

1. Открой `SitePreview.xcodeproj` в этой папке.
2. Вверху Xcode выбери схему **SitePreview**, рядом — **iPhone 17e** или другой симулятор iPhone.
3. Нажми ▶︎ (или **⌘R**).

По умолчанию открывается `http://localhost:4376/ai-bez-lyudey/kursy/`. Если сервер уже работает, больше ничего запускать не нужно.

Если в приложении написано, что страница не открылась, запусти в Терминале из корня репозитория:

```sh
python3 _stati/ios-preview/preview_server.py
```

Оставь это окно открытым. Сервер доступен только на этом Mac. Сообщение «порт занят» обычно означает, что существующий сервер уже работает.

В нижней панели приложения есть **Назад**, **Вперёд**, **Обновить** и меню **На этом Mac / Живой сайт**. Живой адрес — `https://ivan552776.github.io/ai-bez-lyudey/kursy/`. Переключение открывает главную выбранной версии. Свайп от левого края возвращает на предыдущую страницу. Ссылки с открытием нового окна остаются в том же просмотре.

## Что проверить

- Главная → курс → бесплатный урок → назад.
- Статьи → статья → оглавление → раздел → назад.
- Раскрытие частых вопросов, прокрутку и масштабирование двумя пальцами.
- Поворот iPhone, светлую и тёмную тему, увеличенный системный текст.
- Пруд: движение, пауза, уход приложения в фон и возврат.
- В настройках симулятора включить «Уменьшение движения» и повторить просмотр.

Нижняя панель и сайт учитывают безопасные зоны iPhone. Нативные кнопки имеют площадки не меньше 44×44 pt; внешний вид следует теме iOS. Приложение не подменяет настройки цвета и движения страницы.

В Debug-сборке включён Web Inspector: на Mac в Safari открой меню разработки, выбери симулятор и страницу **Просмотр сайта**. Там можно посмотреть ошибки JavaScript. Само приложение не вмешивается в код сайта. Данные просмотра не сохраняются между запусками.

## Сборка без запуска симулятора

Из корня репозитория:

```sh
xcodebuild -project _stati/ios-preview/SitePreview.xcodeproj \
  -scheme SitePreview -configuration Debug -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath _stati/ios-preview/DerivedData \
  CODE_SIGNING_ALLOWED=NO build
```

Схема общая, внешних библиотек нет. `DerivedData`, персональные настройки Xcode и `.DS_Store` исключены из Git.

## Границы проверки

Симулятор помогает найти ошибки iOS/WebKit, размеров и переходов. Он не показывает нагрев, расход батареи и настоящую плавность на iPhone или Android. Это не вебвью Telegram: его кнопки, запуск через бота и ссылки отдельно проверяются внутри Telegram на телефоне.

На настоящем iPhone адрес `localhost` относится к самому телефону. Для проверки этого приложения на телефоне выбирай **Живой сайт**; установка потребует обычной настройки подписи в Xcode. Локальный сервер специально не выставлен в домашнюю сеть.

Если DeviceHub остаётся на «Connecting display» или чёрном экране, это ещё не ошибка сайта: сначала должен запуститься сам симулятор. Успешная сборка также не означает, что сайт проверен вживую.
